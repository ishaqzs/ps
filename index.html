FaraDNS
سرویس DNS پویا و Reverse Proxy برای کاربران فارسی‌زبان
نمای کلی DNS پویا پنل کاربری API و لینک آپدیت Reverse Proxy معماری
سرویس وب کامل شبیه DNSLab

حل مشکل آی‌پی پویا، مدیریت DNS و انتشار سرویس‌های داخلی روی اینترنت، همه در یک پنل فارسی.

FaraDNS به کاربر اجازه می‌دهد ثبت‌نام کند، دامنه یا ساب‌دامنه بگیرد، رکوردهای A / AAAA / CNAME را مدیریت کند و با یک لینک یا API ساده، آی‌پی پویا را از روی مودم، MikroTik، Raspberry Pi و هر دستگاه لینوکسی به‌روز نگه دارد. بخش Reverse Proxy هم امکان انتشار سرویس‌های داخلی بدون آی‌پی ثابت را فراهم می‌کند.

قابلیت‌های اصلی
Dynamic DNS
  • ثبت‌نام و احراز هویت: حساب کاربری، تأیید ایمیل، توکن API.
  • دامنه/ساب‌دامنه: اختصاص hostname به هر کاربر، محدودیت تعداد.
  • مدیریت رکورد: A، AAAA، CNAME با TTL قابل تنظیم.
  • آپدیت خودکار: لینک ساده و API سازگار با DDNS مودم‌ها.
  • لاگ و تاریخچه: ثبت تغییرات آی‌پی و رکوردها با زمان دقیق.
Reverse Proxy
TCP / UDP / HTTP
  • انتشار سرویس داخلی: بدون آی‌پی ثابت، با رزرو پورت یا مسیر.
  • پروفایل‌ها: پروفایل HTTP (هاست‌نیم)، TCP/UDP (پورت).
  • امنیت: محدودیت IP، نرخ درخواست، TLS برای HTTP.

طراحی بخش DNS پویا

این بخش مسئول نگه‌داری رکوردهای DNS و به‌روزرسانی خودکار آی‌پی است تا کاربر بتواند با یک hostname ثابت به شبکه خانگی یا سرور داخلی خود وصل شود.

  • مدل داده: کاربران، دامنه‌ها/ساب‌دامنه‌ها، رکوردها، توکن‌های API، لاگ آپدیت‌ها.
  • رکوردها: پشتیبانی از A، AAAA، CNAME (در صورت نیاز بعداً MX / TXT).
  • DNS Server: اجرای BIND / PowerDNS / CoreDNS با backend دیتابیس یا zoneهای تولیدی.
  • به‌روزرسانی: هر درخواست موفق API، رکورد A/AAAA را با آی‌پی جدید به‌روزرسانی می‌کند.
  • TTL: TTL پیش‌فرض پایین (مثلاً 60 ثانیه) برای واکنش سریع به تغییر آی‌پی. 
// جدول نمونه در دیتابیس (شبه SQL)
users(id, email, password_hash, created_at)

domains(
  id, user_id, hostname,  -- مثلا: user1.faradns.ir
  created_at, is_active
)

records(
  id, domain_id, type,    -- A / AAAA / CNAME
  name,                   -- @ یا www
  value,                  -- IP یا hostname
  ttl, created_at, updated_at
)

api_tokens(
  id, user_id, token, label, last_used_at, created_at
)

update_logs(
  id, domain_id, old_ip, new_ip, user_agent,
  source, created_at      -- source: router, script, panel
)

پنل کاربری فارسی

پنل باید تمیز، سریع و کاملاً فارسی باشد و وضعیت آی‌پی فعلی، رکوردها و تاریخچه آپدیت‌ها را به‌صورت لحظه‌ای نمایش دهد.

  • داشبورد: نمایش آی‌پی فعلی، آخرین زمان آپدیت، وضعیت DNS و Reverse Proxy.
  • مدیریت دامنه: لیست hostnameها، افزودن/حذف، محدودیت بر اساس پلن.
  • مدیریت رکورد: فرم ساده برای A / AAAA / CNAME با اعتبارسنجی.
  • تاریخچه: جدول لاگ آپدیت‌ها با فیلتر بر اساس تاریخ و آی‌پی.
  • توکن API: ساخت، غیرفعال‌سازی و مشاهده آخرین استفاده.

API و لینک آپدیت برای مودم‌ها و اسکریپت‌ها

برای سازگاری با مودم‌های D‑Link، TP‑Link، MikroTik و دستگاه‌های لینوکسی، هم یک URL ساده شبیه سرویس‌های DDNS و هم یک API JSON در نظر گرفته می‌شود.

  • لینک ساده: مناسب مودم‌هایی که فقط URL سفارشی DDNS می‌پذیرند.
  • API JSON: برای اسکریپت‌های شخصی، Raspberry Pi و سرویس‌های بک‌اند.
  • احراز هویت: با توکن در query string یا هدر Authorization.
  • تشخیص آی‌پی: اگر آی‌پی ارسال نشود، از IP درخواست (X‑Forwarded‑For) استفاده می‌شود. 
// ۱) لینک ساده برای مودم‌ها (GET)
https://api.faradns.ir/ddns/update?token=USER_TOKEN&host=home1.faradns.ir

// ۲) API JSON (POST)
POST https://api.faradns.ir/v1/ddns/update
Authorization: Bearer USER_TOKEN
Content-Type: application/json

{
  "hostname": "home1.faradns.ir",
  "ipv4": "203.0.113.42",   // اختیاری، در صورت نبود از آی‌پی درخواست استفاده می‌شود
  "ipv6": "2001:db8::1234"  // اختیاری
}

// پاسخ نمونه
{
  "status": "ok",
  "hostname": "home1.faradns.ir",
  "old_ipv4": "203.0.113.10",
  "new_ipv4": "203.0.113.42",
  "updated_at": "2026-06-20T16:34:00Z"
}

بخش Reverse Proxy برای TCP / UDP / HTTP

این بخش به کاربر اجازه می‌دهد سرویس‌های داخلی (مثلاً وب‌سرور، SSH، دیتابیس یا سرویس UDP) را بدون آی‌پی ثابت روی اینترنت منتشر کند. کاربر می‌تواند پورت یا آدرس دلخواه رزرو کند.

  • HTTP Reverse Proxy: تعریف hostname (مثلاً app1.faradns.ir) و مقصد داخلی (مثلاً 192.168.1.10:8080) با TLS.
  • TCP Proxy: رزرو پورت روی سرور (مثلاً 20022) و هدایت به 192.168.1.10:22 برای SSH.
  • UDP Proxy: برای سرویس‌هایی مثل VoIP یا بازی‌ها، با محدودیت نرخ و فایروال مناسب.
  • Health Check: بررسی در دسترس بودن مقصد داخلی و نمایش وضعیت در پنل. 
// مدل داده ساده برای Reverse Proxy
reverse_endpoints(
  id, user_id,
  type,            -- http / tcp / udp
  public_host,     -- برای http (مثلا app1.faradns.ir)
  public_port,     -- برای tcp/udp (مثلا 20022)
  internal_ip,     -- 192.168.1.10
  internal_port,   -- 22 / 8080 / ...
  protocol,        -- tcp / udp / http
  is_tls,          -- برای http
  created_at, updated_at, is_active
)

معماری کلی سرویس

در این طرح، سرویس به چند بخش اصلی تقسیم می‌شود تا هم مقیاس‌پذیر باشد و هم نگه‌داری آن ساده بماند.

  • وب‌اپ و پنل: Frontend (مثلاً React / Next.js) با رابط فارسی و RTL.
  • Backend API: سرویس REST/GraphQL برای مدیریت کاربران، DNS و Reverse Proxy.
  • DNS Server: سرویس جداگانه (BIND / PowerDNS / CoreDNS) متصل به دیتابیس.
  • Reverse Proxy Edge: خوشه Nginx / Envoy / Traefik برای HTTP/TCP/UDP.
  • Queue / Worker: برای صدور/تمدید TLS، اعمال تغییرات DNS و لاگ‌ها.
  • مانیتورینگ: متریک‌ها، لاگ مرکزی، آلارم برای خطاهای DNS و Proxy.
